# 配置与个性化

> 把 Pi 调教成你喜欢的样子——全局与项目两级设置、快捷键重绑定、主题定制,这是"快速上手"模块的最后一站。

## 学习目标

- 理解全局设置与项目设置的存放位置、合并规则和优先级
- 认识几类高频配置项：模型默认值、UI 显示、网络代理、上下文压缩、消息投递
- 掌握快捷键的默认绑定规律与自定义方法
- 能创建并选用一个自定义主题，理解颜色令牌（color token）体系

## 两级设置：全局与项目

Pi 使用 JSON 格式的设置文件，分两个层级：

| 位置 | 作用范围 |
|------|----------|
| `~/.pi/agent/settings.json` | 全局，对所有项目生效 |
| `.pi/settings.json` | 项目级，仅当前目录生效 |

**项目设置会覆盖全局设置，且嵌套对象是逐字段合并而非整体替换。** 官方文档给出的例子很好地说明了这一点：

```json
// ~/.pi/agent/settings.json（全局）
{
  "theme": "dark",
  "compaction": { "enabled": true, "reserveTokens": 16384 }
}

// .pi/settings.json（项目）
{
  "compaction": { "reserveTokens": 8192 }
}

// 合并结果
{
  "theme": "dark",
  "compaction": { "enabled": true, "reserveTokens": 8192 }
}
```

可以看到，项目设置只覆盖了 `compaction.reserveTokens` 这一个字段，`compaction.enabled` 和顶层的 `theme` 依然沿用全局值。这种"按字段合并"而不是"整个对象整体覆盖"的策略，让你可以在项目里只调整个别参数,而不用把全局配置整份复制粘贴一遍。

两种设置文件都可以直接编辑 JSON，也可以在交互模式下运行 `/settings` 通过面板调整常见选项——面板覆盖不了的冷门配置项，就需要手动编辑文件。

**重要前提：项目设置只有在项目被信任之后才会加载。** 这与《02-快速开始》中介绍的项目信任（trust）机制是同一套逻辑——`.pi/settings.json` 属于"项目本地资源"，Pi 在弹出信任询问之前不会读取它。

## 常用配置项速览

设置项数量很多，这里按主题挑选最常用的几类，完整字段表请查阅仓库文档 `packages/coding-agent/docs/settings.md`。

### 模型与思考强度

```json
{
  "defaultProvider": "anthropic",
  "defaultModel": "claude-sonnet-4-20250514",
  "defaultThinkingLevel": "medium",
  "hideThinkingBlock": false
}
```

`defaultThinkingLevel` 决定新会话默认的思考强度档位（`off` 到 `max` 共 7 档）；`thinkingBudgets` 还可以为各档位自定义具体的 token 预算，例如把 `medium` 档从默认值改成 `10240` token。

### UI 与显示

| 设置 | 默认值 | 作用 |
|------|--------|------|
| `theme` | `"dark"` | 主题名称 |
| `quietStartup` | `false` | 是否隐藏启动头部信息 |
| `doubleEscapeAction` | `"tree"` | 连按两次 Escape 触发的动作：`tree`/`fork`/`none` |
| `tuiMode` | `"regular"` | 交互界面模式：常规滚动 `regular` 或实验性的 `fullscreen`（固定视口）|
| `outputPad` | `1` | 消息内容的横向留白 |

其中 `externalEditor` 值得单独一提：如果你习惯用 VS Code 打开外部编辑器（`Ctrl+G` 触发），配置时必须带上 `--wait` 参数，否则 Pi 不会等编辑器关闭就继续执行：

```json
{
  "externalEditor": "code --wait"
}
```

### 网络代理

```json
{
  "httpProxy": "http://127.0.0.1:7890"
}
```

`httpProxy` 只能在**全局**设置里配置（项目级设置不支持这一项），会被应用为 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量。

### 上下文压缩（Compaction）

```json
{
  "compaction": {
    "enabled": true,
    "reserveTokens": 16384,
    "keepRecentTokens": 20000
  }
}
```

`reserveTokens` 是为模型响应预留的 token 空间，`keepRecentTokens` 是压缩时保留不做摘要的最近对话长度。压缩机制本身（何时触发、如何摘要）属于 Agent 核心原理的一部分，会在后续模块结合源码详细讲解，这里只需要知道它可以通过设置调参。

### 消息投递方式

```json
{
  "steeringMode": "one-at-a-time",
  "followUpMode": "one-at-a-time"
}
```

对应《03-交互模式与CLI命令》中提到的"引导消息"和"后续消息"排队机制：`"all"` 表示排队的多条消息一次性全部发送，`"one-at-a-time"`（默认）表示逐条发送。

### 模型循环列表

```json
{
  "enabledModels": ["claude-*", "gpt-4o", "gemini-2*"]
}
```

与 CLI 的 `--models` 参数格式相同，用于控制 `Ctrl+P`/`Shift+Ctrl+P` 循环切换时会遍历哪些模型，避免在几十个已认证模型里来回翻找。

## 快捷键：默认绑定与自定义

所有快捷键都可以通过 `~/.pi/agent/keybindings.json` 自定义，每个动作可以绑定一个或多个按键。配置文件中使用的是带命名空间的动作 ID（例如 `tui.editor.cursorUp`），旧版本使用的无命名空间 ID（如 `cursorUp`）会在启动时自动迁移。**修改配置后运行 `/reload` 即可生效，无需重启会话。**

### 按键格式

`modifier+key` 的组合形式，修饰键 `ctrl`、`shift`、`alt`、`super` 可以叠加使用，例如 `ctrl+shift+alt+x`、`ctrl+super+k`。`super` 组合键需要终端支持 Kitty keyboard protocol 才能正确识别修饰键,不是所有终端都支持。

### 几个高频默认绑定

| 动作 | 默认按键 | 说明 |
|------|---------|------|
| `app.interrupt` | `escape` | 取消/中止当前操作 |
| `app.clear` | `ctrl+c` | 第一次清空编辑器，第二次退出 |
| `app.editor.external` | `ctrl+g` | 打开外部编辑器 |
| `app.clipboard.pasteImage` | `ctrl+v`（Windows 为 `alt+v`） | 从剪贴板粘贴图片或文本 |
| `app.model.select` | `ctrl+l` | 打开模型选择器 |
| `app.model.cycleForward` / `cycleBackward` | `ctrl+p` / `shift+ctrl+p` | 前后循环切换模型 |
| `app.thinking.cycle` | `shift+tab` | 循环切换思考强度 |
| `app.tools.expand` | `ctrl+o` | 折叠/展开工具输出 |
| `app.message.copy` | `ctrl+x` | 复制最后一条助手消息 |
| `app.message.followUp` | `alt+enter` | 排队后续消息 |

值得注意的一个细节：**如果你把 `tui.editor.historyPrevious`（选择上一条历史输入）绑定到 `ctrl+p`，它会在主编辑器聚焦时优先于模型循环切换的 `ctrl+p` 生效**（但不影响其他选择器场景下 `Ctrl+P` 的默认行为）——这是很多习惯用 shell 历史记录习惯（`ctrl+p`/`ctrl+n`）的用户第一件想做的自定义。

### 自定义示例：Emacs 风格

```json
{
  "tui.editor.historyPrevious": "ctrl+p",
  "tui.editor.historyNext": "ctrl+n",
  "tui.editor.cursorLeft": ["left", "ctrl+b"],
  "tui.editor.cursorRight": ["right", "ctrl+f"],
  "tui.editor.deleteCharForward": ["delete", "ctrl+d"],
  "tui.input.newLine": ["shift+enter", "ctrl+j"]
}
```

### 自定义示例：Vim 风格

```json
{
  "tui.editor.cursorUp": ["up", "alt+k"],
  "tui.editor.cursorDown": ["down", "alt+j"],
  "tui.editor.cursorLeft": ["left", "alt+h"],
  "tui.editor.cursorRight": ["right", "alt+l"]
}
```

数组形式表示"这个动作可以由多个按键触发"，用户配置里的绑定会**整体替换**该动作的默认绑定（不是追加）。另外 Windows 原生终端不支持 Unix 任务控制，因此 `app.suspend`（挂起到后台）在 Windows 上默认没有绑定；如果手动绑定了它，Pi 只会显示一条状态提示而不会真的挂起进程（WSL 环境下则保留正常的 `ctrl+z`/`fg` 行为）。

## 主题定制

主题是定义 TUI 配色的 JSON 文件。Pi 内置 `dark` 和 `light` 两套主题，首次运行时会检测终端背景色自动选用其中一套。

主题的加载来源包括：

- 内置主题
- 全局：`~/.pi/agent/themes/*.json`
- 项目：`.pi/themes/*.json`（同样需要项目已被信任）
- 通过 Pi 包分发的 `themes/` 目录
- 设置文件中 `themes` 数组指定的文件或目录
- CLI 的 `--theme <path>` 参数（可重复传入）

### 创建自定义主题

```bash
mkdir -p ~/.pi/agent/themes
vim ~/.pi/agent/themes/my-theme.json
```

主题文件结构分三部分：`name`（唯一标识，不能包含 `/`）、可选的 `vars`（定义可复用的颜色变量）、以及 `colors`（引用 `vars` 或直接写颜色值）：

```json
{
  "$schema": "https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/modes/interactive/theme/theme-schema.json",
  "name": "my-theme",
  "vars": {
    "primary": "#00aaff",
    "secondary": 242
  },
  "colors": {
    "accent": "primary",
    "border": "primary",
    "success": "#00ff00",
    "error": "#ff0000",
    "text": "",
    "toolTitle": "primary",
    "mdHeading": "#ffaa00"
  }
}
```

`colors` 必须覆盖全部 51 个必需的颜色令牌（`thinkingMax` 和 `scrollbarThumb` 是例外的两个可选项，缺省时分别回退到 `thinkingXhigh` 和 `selectedBg`），大致分为六类：

| 分类 | 数量 | 示例 |
|------|------|------|
| 核心 UI | 11 | `accent`、`border`、`success`、`error`、`text` |
| 背景与内容 | 11（+1 可选） | `userMessageBg`、`toolSuccessBg`、`toolErrorBg` |
| Markdown | 10 | `mdHeading`、`mdCode`、`mdLink` |
| 工具 Diff | 3 | `toolDiffAdded`、`toolDiffRemoved`、`toolDiffContext` |
| 语法高亮 | 9 | `syntaxKeyword`、`syntaxString`、`syntaxFunction` |
| 思考强度边框 | 6（+1 可选） | `thinkingOff` 到 `thinkingMax`,决定编辑器边框随思考档位变化的视觉层级 |

颜色值支持四种写法：6 位十六进制（`"#ff0000"`）、xterm 256 色索引（`39`）、`vars` 变量引用（`"primary"`），或空字符串 `""` 表示"跟随终端默认色"。

创建好之后，在 `/settings` 里选中它，或直接写进设置文件：

```json
{ "theme": "my-theme" }
```

一个很实用的细节：**如果你正在编辑的正是当前生效的自定义主题文件，Pi 会自动热重载**，保存后立刻能在界面上看到效果，不需要 `/reload` 或重启，非常适合边调边看。官方文档也提示可以直接让 Pi 自己帮你写一套主题——把配色需求描述给它，让它生成符合 51 个令牌要求的 JSON 文件。

## 动手练习

1. 在 `.pi/settings.json`（项目级）里覆盖一个全局设置中已有的字段（例如把 `compaction.reserveTokens` 改小),重启 Pi 后用 `/settings` 确认最终生效的值符合"逐字段合并"的预期。
2. 编辑 `~/.pi/agent/keybindings.json`，把 `tui.editor.historyPrevious`/`historyNext` 绑定到 `ctrl+p`/`ctrl+n`，执行 `/reload` 后在编辑器里验证历史记录导航是否生效。
3. 复制内置 `dark` 主题的一份 JSON（或直接照抄本文示例）到 `~/.pi/agent/themes/my-theme.json`，只修改 `accent`、`success`、`error` 三个颜色，通过 `/settings` 切换过去看效果，再尝试直接编辑文件观察热重载。

## 小结

Pi 的配置体系遵循"全局兜底、项目覆盖、按字段合并"的原则,`.pi/settings.json` 依赖项目信任机制才会被加载。常用配置项覆盖模型默认值、UI 显示、网络代理、上下文压缩和消息投递策略等维度。快捷键系统使用命名空间化的动作 ID，全部可以在 `keybindings.json` 中重新绑定并通过 `/reload` 即时生效。主题是遵循 51 个颜色令牌规范的 JSON 文件,支持变量复用和热重载，官方甚至建议直接让 Pi 帮你生成一套。至此，「快速上手」模块的五篇内容已经覆盖了从安装到日常个性化配置的完整闭环。
