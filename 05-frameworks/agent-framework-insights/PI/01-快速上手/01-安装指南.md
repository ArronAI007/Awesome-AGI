# 安装指南

> 在开始阅读 Pi 的任何原理之前，先把它装到本地跑起来——这是理解一切后续内容的地基。

## 学习目标

- 掌握 npm 全局安装 Pi 的标准命令，并理解 `--ignore-scripts` 参数的安全含义
- 了解 macOS/Linux 上的 curl 一键安装脚本适用场景
- 掌握 pnpm/Yarn/Bun 三种替代包管理器的安装与卸载方式
- 知道卸载 Pi 之后哪些数据会被保留、保留在哪里
- 了解 Windows 和 Termux（Android）平台的特殊前置要求

## 为什么先讲安装

Pi 是一个用 TypeScript 编写、以 npm 包形式分发的终端编码 Agent（coding agent，即能自主调用工具、读写文件、执行命令来完成编码任务的智能体）。它的 CLI 名字叫 `pi`，发布为 npm 包 `@earendil-works/pi-coding-agent`。无论你之后是想学习它的运行时原理、扩展系统，还是多模型 API 层，第一步永远是把可执行文件装好、跑起来看看效果。

## npm 全局安装

最标准、跨平台一致的安装方式是通过 npm：

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

### 为什么要加 `--ignore-scripts`

`--ignore-scripts` 会禁用依赖包在安装过程中的生命周期脚本（例如 npm 包的 `postinstall` 钩子）。Pi 官方文档明确说明：**正常的 npm 安装并不需要这些生命周期脚本**，因此禁用它们不会影响 Pi 的功能，却能显著降低供应链攻击的风险——npm 生态里有不少恶意包正是利用 `postinstall` 脚本在安装阶段偷偷执行任意代码。

这不是一个孤立的建议，而是 Pi 项目整体供应链加固策略的一部分。仓库根目录 `README.md` 中提到的相关实践包括：

- 直接依赖锁定精确版本号，`.npmrc` 设置 `save-exact=true`；
- `package-lock.json` 作为依赖的唯一事实来源；
- CI 安装依赖时同样使用 `npm ci --ignore-scripts`；
- 官方发布的本地安装、`pi update --self` 等场景也统一使用 `--ignore-scripts`。

换句话说，"装 Pi 时加 `--ignore-scripts`" 不是一个可选的小技巧，而是这个项目从代码仓库到发布产物一以贯之的安全默认值,建议你在任何场景下安装或升级 Pi 时都保留这个参数。

安装完成后，进入你想让 Pi 工作的项目目录并启动：

```bash
cd /path/to/project
pi
```

Pi 会以当前工作目录为上下文运行，并且可以修改该目录下的文件——这一点在后续讲解「项目信任（trust）」机制时还会展开。

## curl 一键安装脚本（macOS / Linux）

如果你不想手动管理 Node.js 环境，也可以在 macOS 或 Linux 上使用官方提供的一键安装脚本：

```bash
curl -fsSL https://pi.dev/install.sh | sh
```

这个脚本本质上仍然是通过 npm 全局安装 Pi，因此**卸载时同样要用 npm**：

```bash
npm uninstall -g @earendil-works/pi-coding-agent
```

Windows 用户目前没有对应的一键脚本，需要走 npm/pnpm/Yarn/Bun 中的一种方式安装（配合 Windows 的 bash 环境要求，见下文）。

## 使用其他包管理器安装

除了 npm，Pi 也支持通过其他主流包管理器全局安装（命令与 npm 版本等价，只是换了工具）：

```bash
# pnpm
pnpm add -g @earendil-works/pi-coding-agent

# Yarn
yarn global add @earendil-works/pi-coding-agent

# Bun
bun add -g @earendil-works/pi-coding-agent
```

对应的卸载命令分别是：

```bash
# pnpm
pnpm remove -g @earendil-works/pi-coding-agent

# Yarn
yarn global remove @earendil-works/pi-coding-agent

# Bun
bun uninstall -g @earendil-works/pi-coding-agent
```

选择哪种包管理器完全取决于你的个人/团队习惯，功能上没有区别。**核心原则是：用哪个工具装的，就用哪个工具卸载**——curl 安装脚本和 `npm install -g` 都属于 npm 管理的范畴，因此都用 `npm uninstall -g` 卸载。

## 卸载后会保留什么

一个容易被忽视但很重要的细节：**卸载 Pi 本体，不会清空你的个人数据**。以下内容都保存在 `~/.pi/agent/` 目录下，不受卸载 CLI 本身影响：

- 全局设置（`settings.json`）
- 登录凭证（`auth.json`）
- 会话历史（`sessions/` 目录）
- 已安装的 Pi 包（packages，例如通过 `pi install` 装的扩展、Skills 等）

也就是说，如果你只是想重装或升级，不需要担心配置和会话丢失；如果你想彻底清理，需要额外手动删除 `~/.pi/agent/` 目录。

## Windows 平台注意事项

Pi 在 Windows 上运行时**要求存在一个 bash shell**（用于内置的 `bash` 工具执行命令）。启动时它会按以下顺序查找：

1. `~/.pi/agent/settings.json` 中配置的自定义路径（`shellPath`）
2. Git Bash 默认安装路径 `C:\Program Files\Git\bin\bash.exe`
3. `PATH` 中能找到的 `bash.exe`（Cygwin、MSYS2、WSL 都符合条件）

对绝大多数用户来说，安装 [Git for Windows](https://git-scm.com/download/win) 就已经足够（它自带 Git Bash）。如果你使用 Cygwin 等非默认路径的 bash，可以在全局设置里显式指定：

```json
{
  "shellPath": "C:\\cygwin64\\bin\\bash.exe"
}
```

更完整的 Windows 相关行为（如终端全屏模式、快捷键差异）会在后续章节涉及具体功能时提到，详见仓库文档 `packages/coding-agent/docs/windows.md`。

## Termux（Android）平台注意事项

Pi 也可以运行在 Android 的 [Termux](https://termux.dev/) 终端环境中，实现"手机上跑编码 Agent"。核心步骤：

```bash
# 更新包索引
pkg update && pkg upgrade

# 安装依赖：Node.js、Termux:API（剪贴板等设备集成）、git
pkg install nodejs termux-api git

# 安装 pi（同样建议加 --ignore-scripts）
npm install -g --ignore-scripts @earendil-works/pi-coding-agent

# 创建配置目录
mkdir -p ~/.pi/agent

# 运行
pi
```

需要注意的限制（详见仓库文档 `packages/coding-agent/docs/termux.md`）：

- **图片剪贴板不可用**：Termux 的剪贴板 API 只支持文本，`Ctrl+V` 粘贴图片的功能在 Termux 上无效；
- **部分原生依赖不可用**：一些可选的原生模块（例如剪贴板模块）在 Android ARM64 上不可用，安装时会被自动跳过；
- **共享存储访问需要额外授权**：要访问 `/storage/emulated/0`（如 Downloads 目录），需先执行一次 `termux-setup-storage` 授予权限；
- Termux:API 相关命令（`termux-open-url`、`termux-notification` 等）需要额外安装 [Termux:API](https://github.com/termux/termux-api#installation) 这个配套 App，并通过 `pkg install termux-api` 安装命令行工具后才能使用。

如果你打算长期在 Termux 里用 Pi 处理代码任务，官方文档给出了一个可以直接放进 `~/.pi/agent/AGENTS.md` 的示例，用来告诉 Agent 当前所处的 Android/Termux 环境（家目录路径、常用 `termux-*` 命令等），从而让 Agent 给出更贴合手机环境的操作建议。这份 `AGENTS.md` 到底是什么、如何被 Pi 加载，会在下一篇《快速开始》中详细展开。

## 动手练习

1. 在你的机器上执行 `npm install -g --ignore-scripts @earendil-works/pi-coding-agent`，安装完成后运行 `pi -v` 确认版本号能正常输出。
2. 尝试运行 `pi --help`，浏览一下顶层命令行参数，留意是否出现你尚未理解的选项（后续章节会逐一讲解）。
3.（可选）如果你有多台设备，尝试用两种不同的包管理器（例如一台用 npm、一台用 pnpm）分别安装，对比安装速度和体验差异。

## 小结

Pi 的安装方式围绕 npm 生态展开：无论是直接 `npm install -g`，还是 curl 一键脚本，本质都是同一套 npm 包管理流程，卸载时也要对应用 npm 处理。`--ignore-scripts` 不是可有可无的细节，而是 Pi 整个供应链安全策略的第一道防线，任何安装/升级场景都建议保留。卸载 CLI 本身不会清除 `~/.pi/agent/` 下的设置、凭证和会话数据。Windows 需要一个可用的 bash shell（通常装 Git for Windows 即可），Termux 则需要额外的 Termux:API 配合才能获得完整的剪贴板等设备能力。
