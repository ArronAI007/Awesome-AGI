# 快速开始

> 从敲下第一行 `pi` 命令，到让它读懂你的项目、按你的规矩干活——这是本篇要走完的完整链路。

## 学习目标

- 完成 Pi 的首次启动，理解交互式会话的基本形态
- 区分「订阅登录」（`/login`）与「API Key 环境变量」两种认证方式的适用场景
- 走一遍从提问、引用文件、执行 shell 命令到切换模型的完整第一次会话
- 理解 `AGENTS.md`/`CLAUDE.md` 上下文文件的加载规则
- 建立对「项目信任（trust）」机制的基本认知

## 认证：两种方式，两种账单逻辑

Pi 本身不内置模型，它是一个"壳"，需要连接到某个大语言模型 provider（模型提供方，如 Anthropic、OpenAI、Google 等）才能工作。连接前必须完成认证，Pi 支持两条路径：

### 方式一：订阅登录（`/login`）

在 Pi 交互界面里输入：

```text
/login
```

然后从列表中选择一个 provider。Pi 内置支持的订阅制登录包括 Claude Pro/Max、ChatGPT Plus/Pro（Codex）、GitHub Copilot 等。这类登录走的是 OAuth 流程，凭证会保存在 `~/.pi/agent/auth.json` 中，过期后自动刷新。

订阅登录的计费逻辑和你熟悉的官方客户端订阅额度**并不完全等价**——以 Claude Pro/Max 为例，通过第三方 harness（也就是 Pi 这类非官方客户端）使用时，消耗的是 Anthropic 账号的 [extra usage（额外用量）](https://claude.ai/settings/usage) 额度，按 token 计费，而不占用 Claude 官方套餐里的常规对话额度。这是一个容易被忽略但会直接影响你钱包的细节。

### 方式二：API Key（环境变量或凭证文件）

在启动 Pi 之前设置环境变量：

```bash
export ANTHROPIC_API_KEY=sk-ant-...
pi
```

这种方式按 API 调用量直接计费到你的 API Key 账户，和订阅制的额度体系是两套完全独立的账单。除了环境变量，你也可以在交互模式下运行 `/login` 并选择一个"API Key 类型"的 provider，把密钥保存进 `~/.pi/agent/auth.json`（该文件权限被设置为 `0600`，仅当前用户可读写）。**凭证文件中的配置优先级高于环境变量**——如果两者都设置了同一个 provider 的密钥，Pi 会优先使用 `auth.json` 里的那份。

两种方式该怎么选？简单原则：如果你已经在付费订阅 Claude Pro/Max、ChatGPT Plus 等个人订阅,且能接受走 extra usage 计费，`/login` 更省心；如果你是团队/工程场景需要精确控制成本和额度，或者要接入 Anthropic 官方订阅之外的 provider（DeepSeek、Groq、Mistral 等几十家都支持），API Key 环境变量的方式更直接可控。完整的 provider 列表、环境变量名和 `auth.json` 键名对照表，会在《04-Provider与模型配置》中详细展开。

## 第一次会话：完整操作演示

假设你已经完成安装和认证，现在进入某个项目目录并启动：

```bash
cd /path/to/project
pi
```

启动后，Pi 会展示一个交互式界面，直接输入你的请求并回车即可，例如：

```text
Summarize this repository and tell me how to run its checks.
```

Pi 默认给模型配备四个工具：

- `read` —— 读取文件
- `write` —— 创建或覆盖文件
- `edit` —— 对文件打补丁
- `bash` —— 执行 shell 命令

此外还有 `grep`、`find`、`ls` 这几个只读工具，需要通过工具选项显式启用。**Pi 运行在你当前的工作目录，并且真的可以修改这个目录下的文件**——这不是沙箱模拟，是货真价实的文件系统写操作。如果你希望能方便地撤销 Agent 做的改动，务必配合 git 或其他版本控制/checkpoint 工作流一起使用，这样出问题随时可以 `git diff` / `git checkout` 回退。

接下来可以尝试几个典型操作，感受一次真实会话的样子：

**引用文件**：在编辑器里输入 `@` 可以模糊搜索项目文件并插入引用，也可以直接把文件当命令行参数传入：

```bash
pi @README.md "Summarize this"
pi @src/app.ts @src/app.test.ts "Review these together"
```

图片或文本也可以用 `Ctrl+V`（Windows 上是 `Alt+V`）粘贴进编辑器，部分终端还支持直接把图片拖进窗口。

**执行 shell 命令**：在交互模式下，命令前加 `!` 会执行该命令并把输出发给模型：

```text
!npm run lint
```

如果只想自己看结果、不想把输出塞进模型上下文（例如输出很长或包含敏感信息），用双感叹号 `!!command` 即可。

**切换模型**：按 `/model` 命令或 `Ctrl+L` 打开模型选择器；`Shift+Tab` 循环切换 thinking level（思考强度，影响模型分配多少"思考预算"）；`Ctrl+P` / `Shift+Ctrl+P` 在你预先圈定的常用模型集合中前后循环切换。

**结束后继续**：Pi 的会话会自动保存，下次可以直接接着聊：

```bash
pi -c                  # 继续最近一次会话
pi -r                  # 浏览并选择历史会话
pi --name "my task"    # 启动时指定会话显示名称
pi --session <path|id> # 打开指定会话文件
```

会话内还可以用 `/resume`、`/new`、`/tree`、`/fork`、`/clone` 等命令管理会话分支——这些属于「会话」这个更大的主题，本篇不展开，完整机制见后续章节。

**一次性非交互调用**：如果你只是想让 Pi 完成一个任务后直接退出（比如接入脚本或 CI），用 `-p`/`--print` 模式：

```bash
pi -p "Summarize this codebase"
cat README.md | pi -p "Summarize this text"
pi -p @screenshot.png "What's in this image?"
```

还有 `--mode json`（结构化 JSON 事件输出）和 `--mode rpc`（面向进程集成的 RPC 模式），这两种模式面向程序化调用场景，会在后续「协议服务化」章节详细讲解。

## 让 Pi 了解你的项目：AGENTS.md

Pi 在启动时会自动加载"上下文文件"，用来获取项目级别的行为准则。最简单的用法是在项目根目录放一个 `AGENTS.md`：

```markdown
# Project Instructions

- Run `npm run check` after code changes.
- Do not run production migrations locally.
- Keep responses concise.
```

Pi 具体会从以下位置加载上下文文件：

- `~/.pi/agent/AGENTS.md` —— 全局指令，对所有项目生效
- 当前工作目录及其所有父目录中的 `AGENTS.md` 或 `CLAUDE.md`（CLAUDE.md 是为了兼容 Claude Code 等同类工具使用的同名约定文件而设计的别名）

如果某个目录下存在 `AGENTS.override.md`，Pi 会用它**替代**该目录原本的 `AGENTS.md`/`CLAUDE.md`（其他目录层级的上下文文件仍然正常叠加生效，只是这一层被覆盖）。修改了上下文文件之后，需要重启 Pi 或者在会话内执行 `/reload` 才会生效。

## 项目信任（Trust）机制简介

当项目目录中出现项目级的设置文件（`.pi/settings.json`）、项目资源，或者 `.agents/skills` 目录，而 `~/.pi/agent/trust.json` 里又没有针对这个目录（或其父目录）保存过信任决定时，Pi 会在交互式启动时先询问你是否信任这个项目文件夹。

一旦选择信任，Pi 才会：

- 加载 `.pi/settings.json` 里的项目级配置和 `.pi` 目录下的资源（扩展、Skills 等）；
- 自动安装项目声明但本地缺失的 Pi 包；
- 执行项目级的扩展代码。

这个先后顺序是刻意设计的安全边界：在信任决定做出**之前**，Pi 只会加载上下文文件、用户/全局层级的扩展，以及命令行 `-e` 显式指定的扩展，确保这些先加载的部分有能力响应"项目信任"事件；项目本地的扩展、项目包管理的扩展、项目设置，则要等到项目被信任之后才会加载。

非交互模式（`-p`、`--mode json`、`--mode rpc`）不会弹出信任询问，而是直接读取全局设置里的 `defaultProjectTrust`（默认值 `ask`，此时相当于不信任，忽略项目资源；也可设为 `always` 直接信任，或 `never` 一律不信任）。你也可以用 `--approve`/`-a` 或 `--no-approve`/`-na` 为单次运行临时覆盖这个行为。

在交互模式下用 `/trust` 命令可以把当前的信任决定持久化保存下来（写入 `~/.pi/agent/trust.json`，可以选择连同上一级父目录一起信任），但注意它**不会**让当前正在运行的会话立即重新加载——需要重启 Pi 才能生效。

## 动手练习

1. 用 `export ANTHROPIC_API_KEY=...`（或你手上现有的任意受支持 provider 密钥）启动 `pi`，向它提问 "Summarize this repository and tell me how to run its checks."，观察它调用了哪些工具、给出了什么结果。
2. 在一个测试项目的根目录创建一个简单的 `AGENTS.md`，写入一两条你希望 Agent 遵守的规则（比如"每次改动后运行 `npm test`"），重启 Pi 或执行 `/reload`，验证 Agent 的行为是否受到影响。
3. 尝试 `pi -p "用一句话介绍这个项目是做什么的"`，对比非交互模式和交互模式在使用体验上的差异。

## 小结

第一次使用 Pi 的核心链路是：选择一种认证方式（订阅登录走 extra usage 计费，API Key 走独立计费）→ 启动交互会话 → 通过 `@文件引用`、`!shell命令`、`/model` 等基本操作与 Agent 协作 → 用 `AGENTS.md` 把项目规矩告诉它 → 理解项目信任机制如何在"功能便利"与"安全边界"之间做取舍。这些操作构成了日常使用 Pi 的最小闭环，后续章节会在此基础上展开交互模式的全部 slash 命令、CLI 参数细节，以及 Provider 与模型配置的完整图景。
